Arquitectura del Flujo (resumen)

Usuario
  │
  ▼
[ingest.py]  ──►  PREDICT_URL  (NER + intent JointBERT)  http://localhost:8000/predict
             ──►  INTENT_CLASSIFIER_URL  (head de intent) http://localhost:8100/intent
  │
  ├── ¿saludo?           → greeting_node   (respuesta fija)
  ├── ¿fuera de alcance? → scope_block     (respuesta fija)
  ├── ¿calendario?       → RAG             (link de publicación)
  ├── ¿metodología?      → RAG             (documentos técnicos)
  └── datos              → apply_business_rules(ResolvedEntities)
                                    │
                               catalog lookup  →  timeseries JSON
                                    │
                               response.py  →  LLM (OpenAI function calling, streaming)

Crecimiento / PIB Real

PU — Ejemplos
  • cuánto creció la economía en los dos últimos meses
  • Cual es el pib real de los dos últimos años
  • cuánto creció la economía en los últimos 5 años
PREDICT_URL outputsindicator = "imacec" (sesgo del modelo) o "pib", frequency = "m"|"a"|"q", calc_mode = "original"
INTENT_CLASSIFIER headintent = "variation"
Reglas post_classifier Rule09_NivelesNominales.assign_price (rama ECONOMY_GROWTH_RE + YEAR_WORD_RE)
Rule09_NivelesNominales.assign_price (rama PIB_REAL_RE)
Detalle reglas
  • ECONOMY_GROWTH + YEARS: Regex doble "creció/variación/economía" + "años" → fuerza indicator_ent="pib" + frequency_ent="a"
  • PIB_REAL_RE: Texto "pib real" + indicator_ent=="imacec" → corrige a indicator_ent="pib", activa calc_mode_cls="original", añade "(nivel en pesos corrientes)" a la pregunta
Instrucción LLMCuando PIB_REAL_RE activa: inyecta historical_floor_instruction → "REGLA DE SALIDA (PIB REAL): reportar value (nivel), NO usar pct/yoy_pct"
calc_mode resultadoyoy (crecimiento)  |  original (PIB real nivel)
Frecuencia resultadoA (años)  |  Q (trimestral)  |  M (meses) según consulta
Eliminable con mejor modeloSí — eliminables si el clasificador entrena con ejemplos "crecimiento economía en años → PIB anual"
💡 Falencia del clasificador: El modelo tiende a devolver indicator="imacec" para "economía" porque IMACEC es el proxy mensual de la actividad. Las reglas de Rule09 compensan este sesgo para distinguir consultas anuales vs mensuales.

Conclusión y Prioridades


1. Corregir ahora (bug): Rule01_ContribucionGrupal.force_general tiene condición lógicamente imposible y nunca se activa. Revisar la lógica antes de cualquier otra optimización.


2. Compensan gaps del clasificador (eliminables con modelo mejorado):
Rule02, Rule06, Rule07, Rule10, Rule14, RuleGreeting — todas son correcciones de intent/calc_mode que debería emitir directamente el clasificador.


3. Compensan conocimiento de dominio (eliminables con validación en catálogo):
Rule03, Rule04, Rule13 — validan restricciones estructurales (IMACEC=mensual, PIB≠mensual, pisos históricos) que podrían vivir como metadatos del catálogo.


4. Capa de seguridad (mantener siempre):
Rule05 blocklist — neutraliza el sesgo sistemático del modelo de etiquetar OOS como IMACEC. No debe eliminarse aunque mejore el clasificador.
